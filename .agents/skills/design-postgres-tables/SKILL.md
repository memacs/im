# PostgreSQL 表设计

## 核心规则

- 为引用表（用户、订单等）定义 **PRIMARY KEY**。时序/事件/日志表不一定需要；若使用，优先 `BIGINT GENERATED ALWAYS AS IDENTITY`；仅在全球唯一/不透明 ID 场景用 `UUID`。
- **先规范化（至少 3NF）**，消除冗余与更新异常；仅在**实测**读路径 ROI 明确时再反规范化。过早反规范化会增加维护成本。
- 语义上必填的列一律 **NOT NULL**；常用默认值用 **DEFAULT**。
- 为**实际查询路径**建索引：PK/唯一（自动）、**外键列（须手动！）**、高频过滤/排序、JOIN 键。
- 事件时间优先 **TIMESTAMPTZ**；金额 **NUMERIC**；字符串 **TEXT**；整数 **BIGINT**；浮点 **DOUBLE PRECISION**（精确小数用 `NUMERIC`）。

## PostgreSQL 常见陷阱

- **标识符**：未加引号会转小写；避免引号/混合大小写。表名、列名用 `snake_case`。
- **UNIQUE 与 NULL**：UNIQUE 允许多个 NULL。PG15+ 可用 `UNIQUE (...) NULLS NOT DISTINCT` 限制仅一个 NULL。
- **外键索引**：PostgreSQL **不会**自动为外键列建索引，须手动添加。
- **无静默截断**：长度/精度溢出会报错（不像部分库会截断/四舍五入）。例：`NUMERIC(2,0)` 插入 999 会失败。
- **序列/identity 会有空洞**（正常，勿强行连续）。回滚、崩溃、并发会导致 1,2,5,6…，属预期行为。
- **堆存储**：默认无聚簇 PK（不同于 SQL Server/MySQL InnoDB）；`CLUSTER` 是一次性整理，后续插入不维持行序。
- **MVCC**：UPDATE/DELETE 产生死元组，靠 vacuum 清理——设计时避免宽行热点频繁更新。

## 数据类型

- **ID**：优先 `BIGINT GENERATED ALWAYS AS IDENTITY`（`GENERATED BY DEFAULT` 亦可）；合并/联邦/分布式或不透明 ID 用 `UUID`。PG18+ 优先 `uuidv7()`，旧版用 `gen_random_uuid()`。
- **整数**：除非极度在意存储，优先 `BIGINT`；小范围可用 `INTEGER`；慎用 `SMALLINT`。
- **浮点**：优先 `DOUBLE PRECISION`；精确小数用 `NUMERIC`。
- **字符串**：优先 `TEXT`；需长度限制用 `CHECK (LENGTH(col) <= n)` 而非 `VARCHAR(n)`；避免 `CHAR(n)`。二进制用 `BYTEA`。大字段（默认 >2KB）进 TOAST 压缩。大小写不敏感：需要约束时用 `CITEXT` 或 `LOWER(col)` 表达式索引（后者更常见）。
- **金额**：`NUMERIC(p,s)`，**禁止**浮点。
- **时间**：时间戳用 `TIMESTAMPTZ`；仅日期用 `DATE`；时长用 `INTERVAL`。**禁止** `TIMESTAMP`（无时区）。事务开始时间 `now()`，墙钟时间 `clock_timestamp()`。
- **布尔**：需要三态才允许 NULL；否则 `BOOLEAN NOT NULL`。
- **枚举**：`CREATE TYPE ... AS ENUM` 适用于小而稳定的集合；业务常变的枚举用 TEXT/INT + CHECK 或查找表。
- **数组**：`TEXT[]`、`INTEGER[]` 等；元素查询用 **GIN**（`@>`、`<@`、`&&`）。下标从 1 开始。适合标签；关系型数据用关联表，勿用数组代替。
- **范围类型**：`daterange`、`numrange`、`tstzrange`；用 **GiST** 索引；默认边界习惯 `[)`。
- **网络类型**：`INET`、`CIDR`、`MACADDR`。
- **几何类型**：`POINT`、`POLYGON` 等 + **GiST**；高级地理用 **PostGIS**。
- **全文检索**：`TSVECTOR` + **GIN**；`to_tsvector`/`to_tsquery` **必须**指定语言。
- **域类型**：`CREATE DOMAIN` 复用带校验的类型。
- **复合类型**：`CREATE TYPE ... AS (...)` 结构化列。
- **JSONB**：优先于 JSON；用 **GIN** 索引；仅用于可选/半结构化字段。仅当必须保留 JSON 键顺序时才用 JSON。
- **向量**：`pgvector` 的 `vector` 类型。

### 禁止使用的类型

- **禁止** `timestamp`（无时区）→ 用 `timestamptz`
- **禁止** `char(n)` / `varchar(n)` → 用 `text` + CHECK
- **禁止** `money` → 用 `numeric`
- **禁止** `timetz` → 用 `timestamptz`
- **禁止** `timestamptz(0)` 等精度缩写 → 用 `timestamptz`
- **禁止** `serial` → 用 `generated always as identity`

## 表类型

- **普通表**：默认，完全持久、写 WAL。
- **TEMPORARY**：会话级，自动删除，不写 WAL，适合临时计算。
- **UNLOGGED**：持久但崩溃不安全，写入更快，适合可重建缓存/ staging。

## 行级安全（RLS）

`ALTER TABLE tbl ENABLE ROW LEVEL SECURITY`；`CREATE POLICY ... USING (...)` 在行级做访问控制。

## 约束

- **PK**：隐含 UNIQUE + NOT NULL，建 B-tree 索引。
- **FK**：明确 `ON DELETE/UPDATE`（`CASCADE`、`RESTRICT`、`SET NULL` 等）；**引用列须建索引**。循环 FK 可用 `DEFERRABLE INITIALLY DEFERRED`。
- **UNIQUE**：允许多 NULL（除非 `NULLS NOT DISTINCT`）。多数场景建议 `NULLS NOT DISTINCT`。
- **CHECK**：行内约束；NULL 会通过检查（三值逻辑）。要强制非空须配合 `NOT NULL`。
- **EXCLUDE**：防重叠（如房间预订时段），常配合 GiST。

## 索引

- **B-tree**：等值、范围、`ORDER BY` 默认选择。
- **复合索引**：列顺序重要；左前缀原则；高选择性列靠前。
- **覆盖索引**：`INCLUDE (col)` 支持仅索引扫描。
- **部分索引**：热子集，如 `WHERE status = 'active'`。**禁止**谓词含 `NOW()` 等 volatile 函数。
- **表达式索引**：`LOWER(email)` 等，WHERE 须与表达式一致。
- **GIN**：JSONB、数组、全文。
- **GiST**：范围、几何、EXCLUDE。
- **BRIN**：超大且物理顺序与列相关的时序表。

## 分区

- 超大表（如 >1 亿行）且查询稳定带分区键时使用；或便于按周期 prune/批量替换。
- **RANGE**：时序常见；可用 **TimescaleDB** 自动化。
- **LIST**：离散值分区。
- **HASH**：无自然键时均匀分布。
- 使用声明式分区或 hypertable；**勿**用表继承。
- **限制**：全局 UNIQUE 须含分区键；分区表外键受限，可用触发器弥补。

## 特殊场景

### 更新密集表

- 冷热列拆表，减少 bloat。
- `fillfactor=90` 利于 HOT 更新。
- 避免更新已索引列。
- 按更新频率分区。

### 插入密集表

- 索引从简；用 `COPY`/批量 `INSERT`。
- 可重建数据可用 UNLOGGED。
-  bulk load 可先删索引再重建。
- 时间/哈希分区分散写入。
- 自然主键如 `(timestamp, device_id)` 有时更合适；若用代理键优先 **BIGINT identity** 而非 UUID。

### Upsert

- `ON CONFLICT` 目标列须有匹配 **UNIQUE** 索引（部分唯一索引不行）。
- `DO NOTHING` 比无变更的 `DO UPDATE` 更快。

### 安全变更表结构

- 多数 DDL 可放在事务里试跑后 `ROLLBACK`。
- `CREATE INDEX CONCURRENTLY` 不阻塞写，但不能在事务内。
- 带 volatile 默认值的 `NOT NULL` 新列会重写全表。
- 删列前先删依赖约束。
- `CREATE OR REPLACE` 函数参数变化会产生重载，非替换。

## 生成列

- `GENERATED ALWAYS AS (<expr>) STORED` 可索引；PG18+ 有 `VIRTUAL`（不存储）。

## 常用扩展

- **pgcrypto**：`crypt()` 密码哈希。
- **pg_trgm**：模糊匹配 + GIN。
- **citext**：大小写不敏感文本（更常见做法仍是 `LOWER` 索引）。
- **timescaledb**：时序分区、保留、压缩。
- **postgis**：地理空间。
- **pgvector**：向量检索。
- **pgaudit**：审计日志。

## JSONB 指引

- 默认 GIN：`CREATE INDEX ON tbl USING GIN (jsonb_col);`
- **包含**：`jsonb_col @> '{"k":"v"}'` 或数组用 `jsonb_build_array(...)` — **勿**对 JSON **数组**误用 `?`（`?` 仅 object 的 key）。
- 仅 `@>` 负载可考虑 `jsonb_path_ops`（失去 `?`/`?|`/`?&`）。
- 标量等值/范围：生成列或表达式 + B-tree。
- 核心关系放表里，JSONB 放可选属性；可用 CHECK 限制 JSON 形态。

## 示例

### 用户

```sql
CREATE TABLE users (
  user_id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  email TEXT NOT NULL UNIQUE,
  name TEXT NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX ON users (LOWER(email));
CREATE INDEX ON users (created_at);
```

### 订单

```sql
CREATE TABLE orders (
  order_id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  user_id BIGINT NOT NULL REFERENCES users(user_id),
  status TEXT NOT NULL DEFAULT 'PENDING' CHECK (status IN ('PENDING','PAID','CANCELED')),
  total NUMERIC(10,2) NOT NULL CHECK (total > 0),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX ON orders (user_id);
CREATE INDEX ON orders (created_at);
```

### JSONB

```sql
CREATE TABLE profiles (
  user_id BIGINT PRIMARY KEY REFERENCES users(user_id),
  attrs JSONB NOT NULL DEFAULT '{}',
  theme TEXT GENERATED ALWAYS AS (attrs->>'theme') STORED
);
CREATE INDEX profiles_attrs_gin ON profiles USING GIN (attrs);
```
